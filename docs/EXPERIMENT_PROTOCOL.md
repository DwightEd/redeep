# Experiment protocol

## Scope and terminology

This repository evaluates fixed responses generated by `llama-2-7b-chat` with
the internal states of two different scoring backbones:

- `Meta-Llama-3.1-8B-Instruct`
- `Qwen3-8B`

The setup is therefore a **cross-backbone ReDeEP rescoring experiment**, not
the same-generator/same-detector setup used for the paper's main table.  The
RAGTruth text and human span annotations remain fixed; only tokenization and
the mechanistic features come from the scoring backbone.

## Dataset contract

The input files are the official RAGTruth `response.jsonl` and
`source_info.jsonl`.  We retain rows satisfying:

```text
model == "llama-2-7b-chat"
task_type in {"QA", "Data2txt", "Summary"}
```

Expected counts:

| Task | Train | Test | Positive test responses | Raw test labels |
| --- | ---: | ---: | ---: | ---: |
| QA | 839 | 150 | 52 | 85 |
| Data2txt | 883 | 150 | 123 | 213 |
| Summary | 793 | 150 | 51 | 59 |
| Total | 2,515 | 450 | 226 | 357 |

The main paper-compatible test set retains the single truncated QA response.
A `quality == "good"` sensitivity result excludes it.
After overlapping/adjacent labels are unioned, the QA, Data2txt, and Summary
test sets contain 84, 208, and 59 merged spans, respectively.

RAGTruth span coordinates are Unicode character offsets with half-open
semantics, `[start, end)`. Overlapping, adjacent, or duplicate spans are merged
before token labeling. `implicit_true` and `due_to_null` spans remain positive
under the strict RAG-grounding definition.

## Train/dev/test isolation

The official data has train and test splits but no explicit validation split.
From the 2,515 training responses, the code deterministically holds out 50
responses per task using seed 2024:

- calibration-train: feature ranking and MinMax fitting;
- dev: select head count, FFN count, and beta;
- test: evaluate once after all choices are frozen.

No test labels, features, extrema, or task statistics enter calibration.

## Prompt rendering and token labels

Each source prompt is rendered with the scoring model's own chat template,
including the reference implementation's fixed system instruction,
`You are a helpful assistant.` The annotated Llama2 response is appended as
the assistant continuation and teacher-forced through the scorer. Qwen3 always uses
`enable_thinking=False`; template-generated control/thinking tokens are not
part of the evaluated answer.

The complete rendered string is tokenized once with a fast tokenizer and
`return_offsets_mapping=True`.  A response token with interval `[a,b)` is
positive iff it intersects a merged hallucination interval:

```text
b > hallucination_start and a < hallucination_end
```

Special tokens, assistant headers, end-of-turn markers, and padding are
excluded.  In causal alignment, the score at full-sequence position `p+j-1`
is assigned to response token `j` at position `p+j`.

## ReDeEP features

### External Context Score

The primary ECS implementation follows the paper:

1. restrict keys to the retrieved context;
2. find `max(1, floor(0.1 * valid_keys))` context positions for each response
   predictor query and selected attention head;
3. mean-pool the final hidden states at those positions;
4. compute cosine similarity to the final hidden state at the query position.

The public-code behavior, which searches the fixed prompt prefix (system/user
messages plus the assistant header, but never earlier response tokens), is
available as a clearly labeled compatibility mode.

Attention is recomputed only for response queries and relevant keys.  This
avoids materializing every layer's full sequence-by-sequence attention tensor.
Grouped-query attention maps query head `h` to:

```text
kv_head = h // (num_attention_heads // num_key_value_heads)
```

Qwen3 Q/K RMSNorm and each model's rotary embeddings are included.
The target forward pass uses the fixed PyTorch SDPA backend. CPU, disk, and
meta-parameter offload are rejected because feature extraction directly reads
the model's projection weights.

### Parametric Knowledge Score

For each decoder layer, hooks capture the residual stream immediately before
and after its MLP.  Both are decoded with the model's final norm and language
model head.

The primary mode is the standard Jensen-Shannon divergence:

```text
0.5 * KL(P || M) + 0.5 * KL(Q || M), M = 0.5 * (P + Q)
```

It is non-negative and bounded by `ln(2)`.  The compatibility mode reproduces
the public implementation's reverse-KL direction, vocabulary mean, and
`1e6` multiplier.

Token positions are processed in small chunks, so full-vocabulary logits are
released immediately instead of retaining a
`layers × sequence × vocabulary` tensor.

### Copying Heads

The original repository did not publish the script that produced Copying Head
rankings for new models.  This reproduction records that limitation and
implements a deterministic, scalable reconstruction of the paper appendix:

- low-rank OV circuits with the correct GQA value/output head mapping;
- exact cyclic trace calculation without constructing a full vocabulary-by-vocabulary
  matrix;
- fixed-seed sampled Gershgorin/IQR statistics;
- complete per-head scores and approximation metadata.

The top 32 structural candidates are carried into calibration. Published
Llama3 head indices are never silently transferred to Llama-3.1 or Qwen3.

## Calibration

For every JSD/ECS mode:

1. rank candidate ECS features by calibration-train token AUROC in the
   hallucination direction;
2. rank layer PKS features similarly;
3. fit separate MinMax transforms to summed ECS and summed PKS using only
   calibration-train;
4. on dev, search:
   - copying heads: `K = 1..32`;
   - FFN layers: `K = 1..min(32, L)`;
   - `alpha = 1`;
   - `beta = 0.1..1.9`, step `0.1`;
5. maximize the unweighted mean of QA, Data2txt, and Summary literal token
   AUROC.

The selected columns, ranks, extrema, beta, objective value, and chained
code/data/checkpoint/tokenizer/feature-set hashes are serialized before test
evaluation.

## Metrics

For each scoring backbone and each task, the primary metric pools all
evaluated response tokens:

```text
token_micro_auc = AUROC(token_label, token_redeep_score)
```

The paper-compatible secondary metric first averages token scores within each
response and labels a response positive if it contains at least one
hallucination span:

```text
paper_response_auc = AUROC(response_label, mean_token_score)
```

We report QA, Data2txt, Summary, pooled Overall, and the macro average of the
three task AUROCs.  Confidence intervals use response-cluster bootstrap:
sample responses with replacement, then retain all their tokens.  Model
differences use paired response-cluster bootstrap because both scorers evaluate
the same response IDs.

Per-response token AUROC is not a main metric: responses containing only
negative tokens have undefined AUROC.

## Reproducibility artifacts

Every run records:

- Git commit and complete YAML configuration;
- dataset SHA256 values;
- model config SHA256 and model/tokenizer identifiers;
- package, Python, CUDA, and GPU versions;
- full checkpoint-shard and tokenizer-file SHA256 identities;
- Copying Head approximation metadata;
- selected heads/layers and calibration parameters;
- one resumable Parquet feature shard per response;
- machine-readable JSON/CSV results and a Markdown report.
